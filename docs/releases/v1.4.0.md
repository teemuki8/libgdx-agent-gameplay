# libgdx-agent-gameplay 1.4.0 candidate

Resizing or moving the camera while gameplay is paused can leave runtime visual bounds at
the previous viewport. `GameplayRuntimeBridge.refreshPresentationVisuals` lets the application
reproject the last captured world snapshot between ticks, then capture its ordinary presentation
runtime frame. It does not advance gameplay, repeat events, replace domain state or choose the
UI correlation token.

The additive API validates owner-thread/lifecycle access, the completed capture tick, known
unique entity identities and the visual-entry limit before replacing evidence. Capture
completeness retains the existing capacity policy: call `validateCapacity` before the first tick
to reject runtime diagnostics and truncation. The application owns rendering and correlation.

Align `gameplay-core`, `gameplay-libgdx`, `gameplay-runtime` and `gameplay-box2d` on 1.4.0 after
publication. JDK 25 and the existing Box2D backend remain required; the fixture is not published.
