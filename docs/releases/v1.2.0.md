# Gameplay 1.2.0

Gameplay 1.2.0 adds copied-value runtime collision filtering for a bridge-mapped Box2D shape. It is
an additive release over the 1.1.0 public API and does not expose native shape identity.

## Added

- `Box2dCollisionFilter` carries unsigned 16-bit category and mask values plus a signed 16-bit
  group value. Construction rejects values outside those exact ranges with a typed gameplay
  validation diagnostic.
- `GameplayBox2dBridge.configureCollisionFilter(EntityId, Box2dCollisionFilter)` replaces the
  filter on the entity's single mapped shape. Static, kinematic, and dynamic bodies are supported
  while active.
- Filter mutation uses the existing open-bridge, owner-thread, and unlocked-world boundary.
  Missing or inactive mapped bodies are rejected before native mutation.

## Usage

```java
bridge.configureCollisionFilter(
        weaponId,
        new Box2dCollisionFilter(WEAPON_CATEGORY, DAMAGEABLE_MASK, 0));
```

A zero group applies category/mask filtering. Matching positive groups force collision; matching
negative groups prevent collision. The bridge resolves its private `b2ShapeId` internally and
copies all three values into Box2D immediately.

## Native-identity boundary

Applications pass only a stable `EntityId` and an immutable `Box2dCollisionFilter`. They must not
retain, reconstruct, or exchange `b2WorldId`, `b2BodyId`, `b2ShapeId`, `b2JointId`, native structs,
pointers, closures, callback data, or buffers. Collision filtering does not add a native-identity
escape hatch.

The release contains exactly these Maven modules at version `1.2.0`:

- `io.github.teemuki8:gameplay-core`
- `io.github.teemuki8:gameplay-libgdx`
- `io.github.teemuki8:gameplay-runtime`
- `io.github.teemuki8:gameplay-box2d`

`gameplay-fixture` is qualification-only and is not published. Tagging, staging, and Central
publication are separate irreversible operations and are not performed by local qualification.
