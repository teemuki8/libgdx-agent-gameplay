# libgdx-agent-gameplay 1.7.0

Adds canonical vector and quaternion math plus a derived-transform attachment component
for parent-child poses. Existing 2D, 3D, Box2D and Bullet APIs remain compatible.

- `Vec3` gains `add`, `subtract`, `scale`, `dot`, `cross`, `length` and `normalized`;
  `scale` rejects non-finite factors and `normalized` maps the zero vector to itself.
- `QuaternionValue` gains `rotate(Vec3)` (right-handed active rotation), `multiply`
  (Hamilton product, this applied after the argument) and `fromAxisAngle(axis, radians)`.
  These are the canonical implementations consumers should use instead of re-deriving
  the rotation and product formulas per application.
- `AttachedTo(parent, local)` declares that the entity's world transform is composed
  each tick from the parent's resolved transform and the local pose. The world resolves
  every attachment after the ANIMATION phase (the last phase allowed to mutate
  authoritative components) and before the snapshot, bounded to eight chained passes;
  a missing parent freezes the child's last resolved pose, self-attachment and
  non-converging chains fail with `INVALID_ATTACHMENT`. The standard component registry
  and the canonical encoder cover the component.

Publish exactly `gameplay-core`, `gameplay-libgdx`, `gameplay-runtime`, `gameplay-box2d` and
`gameplay-bullet` under `io.github.teemuki8`, all at 1.7.0. The fixture remains unpublished.
JDK 25 and libGDX 1.14.2 remain required. The 2D adapter uses Box2D 3.1.1; 3D rigid dynamics use
Bullet. Consumers explicitly provide desktop natives. Runtime artifacts stay aligned to 3.2.0.

## Compatibility and limits

All five published APIs are compared with 1.6.0 for source and binary compatibility. All
operations remain owner-thread confined and bounded; the application owns world lifecycle and
each fixed step. Attachment resolution is a world-level derivation: it never mutates native
resources and the derived poses do not flow back into commands, physics or deterministic digests.

## Verification

The isolated full check passed 167 tests with no failures, errors or skips, together with
Javadocs, five-module API comparison against published 1.6.0 binaries and archive/POM checks.
The local consumer verification publishes the qualification build and compiles an external
consumer against all five coordinates.
