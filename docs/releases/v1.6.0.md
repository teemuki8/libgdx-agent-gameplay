# libgdx-agent-gameplay 1.6.0

Adds primitive 3D rigid-body simulation and orthographic snapshot rendering for isometric games
and physically controlled ragdolls. Existing 2D, perspective rendering and kinematic Bullet APIs
remain compatible.

- `GameplayBulletDynamicsWorld` owns bounded static/dynamic boxes, Y-axis capsules and spheres,
  copied body state, impulses and oriented 6DoF constraints with application-authored angular limits.
- Bounded central forces and torques act during the next caller-owned fixed step. Applications
  own gait, balance, aiming and recovery policy; the library never installs a character controller.
- Explicit collision-pair filtering suppresses chosen self contacts while preserving world contacts.
  Stable gameplay identities cross the API; native bodies, shapes and constraints remain private.
- `GameplayRenderer3D` accepts orthographic cameras, preserving vertical world span and camera zoom
  on resize, while retaining the existing perspective constructor and snapshot-only rendering.

Publish exactly `gameplay-core`, `gameplay-libgdx`, `gameplay-runtime`, `gameplay-box2d` and
`gameplay-bullet` under `io.github.teemuki8`, all at 1.6.0. The fixture remains unpublished.
JDK 25 and libGDX 1.14.2 remain required. The 2D adapter uses Box2D 3.1.1; 3D rigid dynamics use
Bullet. Consumers explicitly provide desktop natives. Align runtime artifacts to 3.2.0; the optional Bullet adapter depends on `agent-runtime-bullet`.

## Compatibility and limits

All five published APIs are compared with 1.5.0 for source and binary compatibility. All operations
remain owner-thread confined and bounded; the application owns world lifecycle and each fixed step.
Body/constraint budgets are application-selected resource limits, not fixed player-count rules.
The library supplies mechanics for active/passive rigs, without prescribing rig proportions,
locomotion animation, game rules, multiplayer replication or a rendering style.

Native and GL qualification covers Linux software X11. Native Windows/macOS, native Wayland/GPU
and cross-platform deterministic physics are not qualified by this release. The existing japicmp
missing-external-class policy leaves unavailable external supertype changes outside its comparison.

## Verification

The isolated full check passed 152 tests with no failures, errors or skips, together with
Javadocs, five-module API comparison and archive/POM checks. A separate strict-verification
consumer resolved all five release artifacts and exercised native capsule inspection and a
completed contact tick. Runtime 3.2.0 public binaries, sources, Javadocs, POMs and module
metadata were verified against release-key signatures and the exact qualified dependency bytes. The consuming Bootstrap playground separately exercises
real input, runtime/markup comparison, recovery/restart and original-resolution motion review.

Runtime 3.2 integration adds opt-in `GameplayBulletDynamicsWorld.observe`, automatic stable body/shape/joint registration, bounded post-step contact history, and application-owned native joint feedback. Observed steps require a runtime tick; topology edits and native disposal remain outside capture frames. Existing unobserved dynamics and controller APIs remain supported.
