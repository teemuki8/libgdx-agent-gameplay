# libgdx-agent-gameplay 1.5.0

Adds optional 3D gameplay support to the existing fixed-tick GameWorld architecture. The existing
2D APIs and four artifact coordinates remain available; no alternate world or runtime authority
is introduced.

- GL-free immutable Vec3, QuaternionValue, Transform3D, Velocity3D and Aim3D, typed move/aim/fire
  commands, strict prefab codecs, canonical replay digests and explicit runtime projections.
- Snapshot-driven 3D rendering through application-owned camera, ModelBatch and model instances,
  with bounded entries, frustum culling, retained caller GL state and thread/lifecycle checks.
- New optional gameplay-bullet artifact: copied stable-ID ray/capsule query results, bounded
  static-obstacle capsule movement, configurable step/slope/jump behavior and smooth authoritative
  crouch. Native objects remain private; application ownership and disposal stay explicit.

Publish exactly these five coordinates at 1.5.0: gameplay-core, gameplay-libgdx,
gameplay-runtime, gameplay-box2d and gameplay-bullet, all under io.github.teemuki8.
The fixture and Box2D spike remain private. JDK 25, libGDX 1.14.2 and the existing runtime baseline
remain required. Bullet desktop natives must be added explicitly by the consuming application.

## Compatibility and limits

Compare source and binary APIs of the four existing modules against published 1.4.0.
Bullet has no 1.4.0 artifact; its first-release comparison is explicitly unavailable rather than
inventing a baseline. Future baselines at 1.5.0 or newer include it.

The character motor is kinematic against static obstacles; it does not implement dynamic rigid
bodies, networking, moving-platform continuity or character-to-character combat collision.
The 3D renderer bounds entries, while applications must bound model complexity and light counts.
Local native/GL qualification is Linux software X11. The host Wayland/NVIDIA EGL path was not
qualified. Library tests do not substitute for a consumer game's input/UI or visual acceptance.
