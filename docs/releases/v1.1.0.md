# Gameplay 1.1.0

Gameplay 1.1.0 adds a copied-value activation path for repositioning a disabled mapped dynamic
Box2D body without exposing native identity. It is an additive release over the 1.0.0 public API.

## Added

- `Box2dBodyActivation` carries a stable `EntityId`, world pose in render units/radians, linear
  velocity in render units per second, and angular velocity in radians per second.
- `GameplayBox2dBridge.activate(Box2dBodyActivation)` installs those copied values, enables the
  disabled dynamic body, and wakes it.
- Activation uses the existing owner-thread, open-bridge, and unlocked-world mutation boundary.
  Missing bodies and enabled, static, or kinematic bodies are rejected with typed gameplay
  diagnostics. Non-finite angular values and values that cannot be narrowed safely are rejected
  before native mutation.

## Replacing an attachment

Use this exact owner-thread sequence while the world is unlocked:

1. Copy the destination body's state with `bodyState`.
2. Disable the attached dynamic body with `deactivate`.
3. Remove the previous bridge-owned joint with `removeJoint`.
4. Activate the body from the copied destination pose and velocity with `activate`.
5. Create the replacement joint with `createRevoluteJoint`.

`deactivate` retains the mapped body and does not remove connected joints. `removeJoint` remains
idempotent for an absent stable joint ID. Joint creation follows activation so the endpoint is
already enabled at its new pose.

```java
Box2dBodyState palm = bridge.bodyState(palmId).orElseThrow();
bridge.deactivate(weaponId);
bridge.removeJoint(attachmentId);
bridge.activate(new Box2dBodyActivation(
        weaponId,
        palm.positionRenderUnits(),
        palm.angleRadians(),
        palm.velocityRenderUnitsPerSecond(),
        palm.angularVelocityRadiansPerSecond()));
bridge.createRevoluteJoint(new Box2dRevoluteJointSpec(
        attachmentId, palmId, weaponId, palm.positionRenderUnits(),
        lowerAngleRadians, upperAngleRadians, false));
```

## Native-identity boundary

The activation and attachment APIs accept only stable gameplay IDs and immutable copied values.
Applications must not retain, reconstruct, or exchange `b2WorldId`, `b2BodyId`, `b2ShapeId`,
`b2JointId`, native structs, pointers, closures, callback data, or buffers. The bridge resolves its
private native mappings internally and returns copied body, joint, contact, and ray evidence.
